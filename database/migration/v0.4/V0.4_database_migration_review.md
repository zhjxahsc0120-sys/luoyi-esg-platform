## 3. 影响表与字段

### 3.1 修改表

| 表 | 新增内容 | 业务规则 |
|---|---|---|
| `e_rectification_task` | `rectification_completed_date DATE NULL`；`rectification_completed_by BIGINT NULL` | 完成日期由甲方填报；系统不得自动生成；提交复核前由业务/API校验必填。完成日期允许历史记录为空。 |

| `permit_record` | `project_id BIGINT NULL` | 历史记录允许为空；新建许可事实应由 API 强制提供项目归属。 |

### 3.2 新增表

`special_plan_approval` 用于记录风险源对应的专项方案审批事实，包含：

- 项目归属：`project_id`
- 风险源关联：`risk_point_id`
- 方案标识：`plan_code`、`plan_name`
- 风险等级：`risk_level`
- 审批状态和日期：`approval_status`、`approval_date`
- 资料关联：`approval_file_id`
- 来源与 Demo 标识：`source_doc_ref`、`data_nature`、`is_demo`
- 记录时间：`created_at`、`updated_at`

批准索引为：

- 主键：`id`
- 唯一键：`(project_id, plan_code)`
- `risk_point_id`
- `(project_id, approval_status)`
- `(project_id, approval_date)`
- `(project_id, risk_level)`

### 3.3 仅作为外键目标、未修改的表

## 5. 重要未包含项

### G04 域约束

当前 `e_closure_case.ck_e_case_domain` 仅允许既有域值（实施前核查为 E01/E02/E03）。V0.4 需要接入 G04，但扩展该 CHECK 约束通常需要删除并重建约束，超出本次“仅新增批准字段、新表、索引和外键”的脚本范围，也会触及本任务禁止生成的破坏性约束操作。

因此：

- 本脚本没有修改 `ck_e_case_domain`；
- 本脚本执行后不能直接据此认定 G04 数据已可迁移；
- G04 域约束扩展必须形成独立、人工批准的约束变更脚本后再执行。

同时不包含历史数据回填、Demo 数据插入、视图修改、API 调整和前端调整。

## 6. 风险清单

1. **重复执行风险**：脚本未设计为幂等脚本。重复执行可能因字段、表、索引或约束已存在而失败，执行前必须进行 `information_schema` 只读检查。
2. **历史项目归属为空**：五个新增项目字段均允许历史 `NULL`，后续 API 新写入必须强制项目归属，否则无法稳定进行项目级统计。
3. **专项方案孤儿引用**：新增专项方案记录必须先确认 `safety_risk_point.id` 存在，审批文件关联同理。
4. **项目主数据未建外键**：`project_id` 暂不受物理外键保护，需要在 API、数据模板和后续项目主数据方案中补足校验。
5. **G01/G02 重复统计**：审批、许可、专项方案三类事实必须以统一控制键和明确映射去重；禁止按名称模糊合并。
6. **S03 口径漂移**：必须继续使用 `payment_rate`，跨周期汇总时按 `worker_count` 做人数加权；本脚本不改变该逻辑。
7. **整改完成时间合规风险**：`rectification_completed_date` 只能由甲方填报，系统不得用关闭时间或当前时间自动代替。
