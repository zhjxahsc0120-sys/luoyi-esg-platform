## 2. 口径与 KPI 主源

### 2.1 统计口径

当前未闭环水土保持问题事项数；一事项只计 1；已闭环、已撤销、已合并不计。  
逾期是叠加属性，不加入「全部未闭环」等式。

### 2.2 闭环条件

同 E02 V1.0：

> 整改完成 + 复查通过 + 可追溯销项确认 → CLOSED。  
> 复查通过 ≠ KPI−1。

### 2.3 KPI 唯一主源与切主源门禁（冻结）

参照 E02 V1.0 §2.3，并补齐一级统计条状态分项口径：

1. **切换前：** `water_protection_issue` 是正式和演示 KPI 的**唯一计数主源**。  
2. **切换前一级统计条**中的「全部未闭环」以及「整改中 / 待复查 / 待销项 / 暂缓」等**状态分项数量**，均以 `water_protection_issue` 为计数基础，通过下方**台账状态映射**计算。  
3. `e_closure_case.current_status` **只用于**详情展示和双轨对账，**不参与**切换前 KPI 及其状态分项计数。  
4. `e_closure_case(E03_WATER)` 切换前**只提供**责任、轨迹、材料、GIS 等闭环详情。  
5. **两表任何阶段不得相加。**  
6. **一条台账记录只能关联一条有效 E03 案卷。**  
7. P2 API 稳定且双轨只读对账通过后，**才能在实施任务单中明确切主源时间**。  
8. 切换前后**分别验收**正式计数和演示计数。  

**台账状态 → 一级统计项映射（冻结）：**

| `water_protection_issue.issue_status` | 一级统计项 | 计入全部未闭环 |
|---------------------------------------|------------|----------------|
| 已发现、待整改、整改中 | 整改中 | 是 |
| 待复查 | 待复查 | 是 |
| 待销项 | 待销项 | 是 |
| 暂缓 | 暂缓（业务启用后有数据再单列） | 是（若启用） |
| 已闭环、已撤销、已合并 | 不计入 | 否 |

**双轨不一致处理（冻结）：**

- 台账 `issue_status` 与案卷 `current_status` 映射结果不一致时，**不得由前端临时选取其中一方**。  
- 进入**双轨对账异常清单**。  
- **切换前仍以台账状态为准**计入 KPI 与一级统计条。

关联约束（冻结）：

```text
source_table     = 'water_protection_issue'
source_record_id = 水保台账主键
case_domain      = 'E03_WATER'
```

### 2.4 切换前 KPI 查询条件（冻结）

**禁止**继续使用：

```sql
issue_status <> '已闭环'
```

**切换前正式 KPI：**

```sql
water_protection_issue
WHERE issue_status NOT IN ('已闭环', '已撤销', '已合并')
  AND is_demo = 0
  AND data_nature = 'formal'
  AND effective_status = 'EFFECTIVE'
```

**切换前演示 KPI：**

```sql
water_protection_issue
WHERE issue_status NOT IN ('已闭环', '已撤销', '已合并')
  AND is_demo = 1
  AND data_nature = 'demo'
  AND effective_status = 'EFFECTIVE'
```

若现表暂无 `effective_status`：

- P1 以**独立、幂等增量迁移**补齐该字段；或  
- 服务端使用**等价有效性规则**（须在实施任务单写明具体谓词）。  

历史空状态、异常状态**不得默认计入**，进入**待核实清单**。

### 2.5 P1 演示双写完整规则（冻结）

每条演示事项同时写入：

1. `water_protection_issue`  
2. `e_closure_case(case_domain='E03_WATER')`  
3. 二者通过 `source_table + source_record_id` **一对一**关联  

两边均需具备：

```text
is_demo = 1
data_nature = 'demo'
```

若台账表缺字段：**只允许**通过独立、幂等的增量迁移补齐；**不得**修改历史建库脚本。

### 2.6 存量种子处理规则（冻结）

针对现网 `710001–710007`（及同类历史记录）：

| 核实结果 | 处理 |
|----------|------|
| 能证明是历史演示种子 | **原位补标** `is_demo=1`、`data_nature='demo'` |
| 能证明是真实业务记录 | 继续保留 formal |
| 来源不明 | 进入**待核实清单**，暂不纳入正式有效统计 |

硬规则：

- **不删除**历史记录  
- **不擅自「迁出」**  
- **不得**为凑出正式 KPI=0，将来源不明记录批量改为 demo  
- 正式 KPI 是否为 0 **由数据事实决定**，不能作为数据清洗目标

## 5. 一级总览面板

### 5.1 命名与尺寸

- 面板标题：**「水土保持问题闭环工作台」**（水保即水土保持）  
- 宽度复用 E01/E02 容器；高度占满右侧工作区；笔记本统计可换行；分页栏始终可见  
- 分页默认每页 3 条；同分辨率不得动态跳变  

### 5.2 统计条（冻结）

**计数基础（与 §2.3 一致，冻结）：**

- 切换前，一级统计条「全部未闭环」及「整改中 / 待复查 / 待销项 / 暂缓」**一律**按 `water_protection_issue.issue_status` + §2.3 台账状态映射计数。  
- **禁止**按 `e_closure_case.current_status` 计算切换前一级统计条或 KPI 分项。  
- 案卷枚举（DISCOVERED / RECTIFYING / PENDING_REVIEW 等）仅可出现在详情展示、对账与切主源后的目标态；**不得**在切换前倒灌一级统计。

| 一级统计项 | 台账 `issue_status`（见 §2.3） | 计入全部未闭环 |
|------------|--------------------------------|----------------|
| 整改中 | 已发现、待整改、整改中 | 是 |
| 待复查 | 待复查 | 是 |
| 待销项 | 待销项 | 是 |
| 暂缓 | 暂缓（启用后） | 是（若启用） |
| （不展示计数） | 已闭环、已撤销、已合并 | **否** |

等式：

```text
全部未闭环 = 整改中 + 待复查 + 待销项 [+ 暂缓（若启用）]
```

该等式两边均来自同一台账映射结果，不得混用案卷状态导致等式不成立。

逾期：「其中逾期 m」，已计入上式，不可再与状态格相加。

**禁止**仅用 `issue_status <> '已闭环'`。

### 5.3 P1 固定验收场景与数字（冻结）

#### 5.3.1 E03-D01～D07 逐项定义（最小验收场景表）

| 编号 | 台账状态（一级映射） | 是否逾期 | 是否计入未闭环 | 材料要点 |
|------|----------------------|----------|----------------|----------|
| E03-D01 | 整改中 | 否 | 是 | 通知或初始报告 |
| E03-D02 | 整改中 | **是** | 是 | 通知或初始报告 |
| E03-D03 | 待复查 | 否 | 是 | 通知＋本轮整改材料 |
| E03-D04 | 待销项 | 否 | 是 | 通知＋整改材料＋复查意见 |
| E03-D05 | 已闭环 | 否 | **否** | 含销项材料或合规的等价销项确认 |
| E03-D06 | 已合并 | 否 | **否** | 保留合并关系，不计 KPI |
| E03-D07 | 复查退回后整改中 | 否 | 是 | 通知＋上轮整改＋退回意见；本轮整改待补；完整度 **3/4**（见 §8.4） |

说明：

- D07 的一级统计项归入**整改中**（台账 `issue_status` 为整改中或等价退回后整改中）。  
- D01～D07 均须满足 §2.5 演示双写（台账 + `e_closure_case(E03_WATER)` 一对一）；切换前计数仍只读台账侧。

#### 5.3.2 汇总验收数字

由此稳定得到：

| 验收项 | 预期 | 构成 |
|--------|------|------|
| 未闭环总数 | **5** | D01+D02+D03+D04+D07 |
| 整改中 | **3** | D01、D02、D07 |
| 待复查 | **1** | D03 |
| 待销项 | **1** | D04 |
| 其中逾期 | **1** | 仅 D02（叠加，不加入总数） |
| 已闭环、不计 | 1 | D05 |
| 已合并、不计 | 1 | D06 |

核对等式：

```text
未闭环 5
= 整改中 3（D01、D02、D07）
+ 待复查 1（D03）
+ 待销项 1（D04）

5 = 3 + 1 + 1
```

D05、D06 不计入；D02 为唯一逾期事项。

## 8. 材料完整度与轮次识别（冻结）

### 8.1 规范引用

材料角色与计算规则**版本化引用 E02 V1.0 §8**；等价销项确认**必须满足 E02 V1.0 §8.4**：确认人、确认时间、确认意见、依据、权限校验。  
**普通 CLOSED 状态轨迹不能充当销项材料。**

### 8.2 公共材料角色枚举（底层共用，不另造一套）

`FORMAL_NOTICE`、`INITIAL_REPORT`、`RECTIFICATION_MATERIAL`、`REVIEW_OPINION`、`RETEST_REPORT`、`CLOSURE_DOCUMENT`

前端名称与必需性配置可按水土保持业务展示。

### 8.3 轮次识别技术依据（冻结一种）

冻结采用：

```text
e_case_evidence.rectification_round_id
```

若现列不存在：P1 以独立幂等增量迁移补齐；并与 `e_case_status_history` / `e_case_rectification_link` / `e_rectification_task` 可关联。  

备选等价（仅当实施单写明且能关联轨迹时允许）：

```text
round_no + 与状态轨迹的结构化关联
```
