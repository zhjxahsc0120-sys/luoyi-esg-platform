## 1. 指标定义与范围

### 1.1 指标定义

S01 表示罗宜高速项目自统计起点或最近一次已生效重置日起，连续未发生“造成人员死亡的安全生产责任事故”所经过的完整自然日数。

### 1.2 项目范围

- 统计对象：罗宜高速项目建设期纳入项目安全生产管理边界的全部施工活动。
- 统计粒度：项目级，不按标段分别形成首页主值。
- 标段、责任单位可作为事故记录属性下钻，但不得对各标段天数求和或平均。
- 统计起点：开工令日期 **2026-05-08**。
- 2026-05-08 以前的施工期事故、风险、整改或阶段演示记录不得进入 S01。

### 1.3 本阶段不做

- 不做地图联动工作台。
- 不建设事故审批流程 UI。
- 不与 S02 较大及以上安全风险点混计。
- 不把一般隐患、未遂事件、轻微伤害或普通设备故障计入重置。
- 不把“安全月报已上传”自动等同于“建设单位已确认”。
- 不修改首页 KPI 卡片版式及其他 11 个 KPI。

## 2. 连续天数口径

### 2.1 唯一算法

\[
\text{continuousDays}
=
(\text{statisticsAsOf}-\text{cycleStartDate}).\text{days}
\]

- `cycleStartDate`：最近一次已生效重置事故的发生日期；无重置时为 **2026-05-08**。
- `statisticsAsOf`：该条确认快照对应的统计期末业务日期。
- 采用自然日，不扣除节假日、停工期或非作业日。
- 统计起点当天为 `0` 天；次日为 `1` 天。该定义表示“已经完整经过的安全生产自然日数”。
- 日期按项目业务时区 `Asia/Shanghai` 归一为日期后计算，禁止用时间戳小时差直接除以 24。
- 前端不得使用浏览器当前时间或开工日重新计算主值。

### 2.2 固定验收基线

无生效重置时：

`2026-07-24 - 2026-05-08 = 77 天`

V0.2 将 **77 天**作为设计验收样例；现网旧基线 **368 天**仅用于说明历史差异，不再作为新测数依据。

### 2.3 生产环境统计日

- 验收模式 `?acceptance=1`：固定 `statisticsAsOf=2026-07-24`，确保截图与自动化测试稳定。
- 正式模式：使用后端返回的最新有效确认快照日期，不得由前端取“今天”替换。
- 若最新确认快照早于平台当前业务日，必须同时显示“截至 YYYY-MM-DD”，不得把旧快照包装成实时值。

## 3. 重置规则与状态机

### 3.1 唯一重置条件

一条事故只有同时满足下列条件才可重置：

1. 属于罗宜高速项目安全生产管理边界；
2. 事故责任认定结果为**安全生产责任事故**；
3. `fatality_count >= 1`；
4. 认定记录已生效，且事故记录、认定记录均为当前有效版本；
5. 正式 KPI 仅使用正式、非演示事故记录。

`interrupt_counting` 保留时只能作为上述规则计算出的审计结果，不得作为可脱离硬条件单独编辑的业务开关。

### 3.2 明确不重置

- 一般安全隐患；
- 未遂事件；
- 无人员死亡的轻微伤害；
- 普通设备故障；
- 责任性质尚未认定的事故；
- 已撤销、无效、被替代或演示事故记录。

### 3.3 待认定与追溯

| 状态 | KPI 处理 |
|---|---|
| 无待认定事故 | `CONTINUOUS`，按当前周期计数 |
| 存在可能触发重置但尚未认定的事故 | `PENDING_DETERMINATION`；暂不改变 `cycleStartDate`，页面明确“存在待认定事故” |
| 后续认定为造成人员死亡的安全生产责任事故 | 从**事故发生日**追溯形成新周期 |
| 后续认定不满足重置条件 | 关闭待认定提示，不重置 |

认定结果生效后应生成新的确认快照。既有月度确认快照只增不改，用于保留当时认定状态与审计轨迹。

### 3.4 最近一次重置

- 有重置：显示事故发生日期和经审核的重置原因摘要。
- 无重置：显示“自开工令 2026-05-08 起未发生触发重置的事故”。
- 不得把一般隐患或 S02 风险点作为“最近一次重置原因”。

## 4. KPI 唯一主源与数据门禁

### 4.1 主源

| 对象 | 主源 | 作用 |
|---|---|---|
| 连续天数确认快照 | `safety_production_record` | S01 主值、统计日、周期起点、确认状态 |
| 事故及认定 | `safety_incident_record` 及当前有效认定信息 | 判断是否重置及最近重置 |
| 当前工期阶段 | `construction_stage_record` | 仅展示，不参与天数计算 |

首页 `/api/dashboard/kpis` 的 S01 与详情 `GET /api/dashboard/kpi/S01` 必须调用同一后端服务结果。首页值等于详情的 `continuousDays`。

### 4.2 正式主路径

正式主值必须同时满足：

```text
project_id = 当前项目
data_nature = formal
is_demo = 0
effective_status = EFFECTIVE
verification_status = VERIFIED
confirmation_status = CONFIRMED
is_current = 1
confirmation_batch_id = 当前正式确认批次
statistics_as_of <= 平台业务统计日
```

同一项目、同一数据性质、同一统计期末只允许一个当前有效确认快照。查询存在多条时不得静默取第一条，必须记录数据门禁异常。

### 4.3 无正式确认数据

- 没有任何有效正式确认快照：主值显示 `--`，状态显示“待建设单位确认”。
- 禁止用 `0` 代替缺失值，避免被误读为“当天发生重置”。
- 禁止自动回退到演示数据、Mock、JSON 或前端重算值。
- 如需查看演示模式，必须由部署/验收模式明确选择，且显示一个全局“演示数据”标识。

### 4.4 演示主路径

演示数据必须满足：

```text
project_id = 当前项目
data_nature = demo
is_demo = 1
effective_status = EFFECTIVE
is_current = 1
demo_batch_code = DEMO-S01-20260724
```

演示基线：开工令 `2026-05-08`，统计日 `2026-07-24`，无触发重置事故，连续 `77` 天。

| 字段 | 说明 |

| `effective_status` | `EFFECTIVE` / `INEFFECTIVE` |

| `data_nature` / `is_demo` | 正式与演示隔离 |
| `confirmed_at` / `confirmed_by` | 确认审计字段 |

### 5.2 `safety_incident_record`

建议补齐：

| 字段 | 说明 |
|---|---|
| `occurred_date` | 事故发生日期；重置时作为周期起点 |
| `fatality_count` | 死亡人数；不用单一布尔值替代 |
| `responsibility_determination_status` | `PENDING` / `RESPONSIBLE` / `NON_RESPONSIBLE` |
| `determination_effective_date` | 认定生效日期 |
| `interrupt_counting` | 由硬条件计算的审计结果 |
| `effective_status` / `is_current` | 有效版本控制 |
| `data_nature` / `is_demo` | 正式与演示隔离 |

### 5.3 确认批次

建议新增 `s01_confirmation_batch`，保存确认月份、统计期末、确认单位、确认人、确认时间、状态、数据性质及版本。月度确认通过新增批次和快照实现，禁止覆盖历史确认结果。

### 5.4 工期阶段

- 只读取 `construction_stage_record` 中当前有效且与统计日相符的阶段。
- S01、首页和其他专题必须使用同一阶段名称。
- 本轮验收预期为“路基桥涵施工”；若无有效正式记录，显示“资料待补齐”，不得硬编码其他阶段。
- 工期阶段仅用于背景说明，不参与 S01 计数和重置。

## 6. 资料与证据优先级

| 优先级 | 资料 | 用途 |
|---|---|---|
| 1 | 事故调查报告、事故责任认定或正式处理决定 | 认定责任性质、死亡人数及是否触发重置 |
| 2 | 事故快报、续报 | 形成待认定事故，不直接触发生效重置 |
| 3 | 建设单位月度确认记录 | 形成 S01 正式确认批次与快照 |
| 4 | 施工日志、安全月报、监理日志、监理月报 | 交叉核验事故和统计期间，不单独决定重置 |

证据缺失或认定未生效时不得擅自按标题、描述或伤害关键词触发重置。

4. 底部：一句业务结论和资料来源说明。

无重置演示结论：

> 项目开工以来，截至 2026-07-24 已连续安全生产 77 天，未发生触发重置的人员死亡安全生产责任事故。

- 6 个摘要卡堆叠；
- 30/60/90 天节点；
- 12 个月状态宫格；
- 大段计数规则说教；
- 独立证据表格；
- “发起督办”按钮；

### 8.4 首页卡片边界
