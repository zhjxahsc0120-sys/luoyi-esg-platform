# 罗宜高速 ESG Cesium 地图模块接入与替换说明

## 1. 交接目的

本交接包用于把当前已经验证的 Cesium 首页地图整体移入另一套 Vue 3 ESG 项目，替换此前的演示地图。

当前正式地图效果包括：

- 默认加载实际道路生态关键要素 KML。
- 默认加载 SPX 边坡图层；SPX 由 Web Worker 解析并批量渲染，避免浏览器因十万级线段实体崩溃。
- 首次进入按新道路中心线范围定位。
- 保留 KML 原始坐标、颜色、透明度、线宽和线型。
- 显示基本农田、保护区、生态保护要素名称。
- 8 个堆渣区域显示为“堆渣区1”至“堆渣区8”，原 KML 名称保存在 `sourceFeatureName` 属性中。
- 暂时隐藏有数据质量问题的“取弃土场”“弃渣场”“0土场编号”和 `q数字` 要素。
- 首页不再加载旧“1标段、2标段、3标段”演示路线。
- 可选接入后台 ESG 异常、超标、逾期点位，点击点位可查看详情及业务关联。
- 支持底图切换、地形、视角复位、历史卷帘/双屏对比、地图全屏和点击拾取。

## 2. 技术基线

| 项目 | 当前版本/要求 |
| --- | --- |
| 前端 | Vue 3 + TypeScript |
| 构建 | Vite 5 |
| Cesium | `^1.143.0` |
| 图标 | `lucide-vue-next` |
| 静态资源复制 | `vite-plugin-static-copy` |
| 坐标 | KML 原始经纬度坐标，Cesium 按 WGS84 经纬度读取 |
| 后台业务接口 | 默认 `/api/esg/gis`，可用环境变量替换 |

至少安装：

```bash
npm install cesium@^1.143.0 lucide-vue-next@^0.511.0
npm install -D vite-plugin-static-copy@^3.4.0
```

## 4. 最快接入步骤

### 第一步：复制地图核心

将交接包中的：

```text
src/modules/traffic-gis-overview
```

整体复制到目标 ESG 项目的：

```text
目标项目/src/modules/traffic-gis-overview
```

不要只复制 `TrafficGisOverview.vue`。该组件依赖 `cesium/core`、`cesium/layers`、`cesium/renderers`、`adapters`、`types` 和 `config` 等目录。

### 第二步：复制 KML 和配置

将：

```text
public/gis/s1-6
```

整体复制到：

```text
目标项目/public/gis/s1-6
```

必须保持以下 URL 可访问：

```text
/gis/s1-6/layer-config.json
/gis/s1-6/layers/高速公路首页_道路生态关键要素_不含SPX.kml
/gis/s1-6/layers/高速公路首页_SPX边坡_独立图层.kml
```

不要修改两份 KML 的坐标、颜色、透明度和线宽。

### 第三步：合并 Vite 的 Cesium 配置

参考 `integration-examples/vite.config.reference.ts`，把以下能力合并到目标项目现有 `vite.config.ts`，不要直接覆盖同事已有的代理和插件。

关键配置：

```ts
import { viteStaticCopy } from 'vite-plugin-static-copy'

viteStaticCopy({
  targets: [
    { src: 'node_modules/cesium/Build/Cesium/Workers/**/*', dest: 'cesium/Workers' },
    { src: 'node_modules/cesium/Build/Cesium/Assets/**/*', dest: 'cesium/Assets' },
    { src: 'node_modules/cesium/Build/Cesium/Widgets/**/*', dest: 'cesium/Widgets' },
    { src: 'node_modules/cesium/Build/Cesium/ThirdParty/**/*', dest: 'cesium/ThirdParty' },
  ],
})
```

并加入：

```ts
define: {
  CESIUM_BASE_URL: JSON.stringify(command === 'serve'
    ? '/node_modules/cesium/Build/Cesium'
    : '/cesium'),
},
```

推荐把 Cesium 和地图模块拆包：

```ts
build: {
  rollupOptions: {
    output: {
      manualChunks(id) {
        if (id.includes('node_modules/cesium')) return 'cesium'
        if (id.includes('src/modules/traffic-gis-overview')) {
          return 'traffic-gis-overview'
        }
      },
    },
  },
},
```

### 第四步：先做独立预览

可参考 `integration-examples/GisPreviewPage.vue` 注册一个临时路由。只验证设计地图时使用：

```vue
<TrafficGisOverview
  project-id="LUOYI-ESG"
  data-mode="api"
  :design-only="true"
  presentation-mode="preview"
  :show-legend="true"
  :show-mode-switch="false"
  :show-config-button="true"
  :interaction-enabled="true"
/>
```

`design-only="true"` 表示只加载两份正式 KML，不请求后台异常点接口。

### 第五步：嵌入 ESG 首页

目标项目可直接复制 `GisOverviewCesiumPanel.vue`。如果目标项目没有相同的 `PanelCard.vue`，可：

1. 一并复制交接包中的 `PanelCard.vue`；或
2. 删除 `PanelCard` 外层，只保留固定高度容器和 `TrafficGisOverview`。

首页推荐参数：

```vue
<TrafficGisOverview
  project-id="LUOYI-ESG"
  data-mode="api"
  :show-legend="true"
  :show-mode-switch="true"
  :show-config-button="true"
  :interaction-enabled="true"
  :design-only="false"
  presentation-mode="dashboard"
  @feature-click="handleFeatureClick"
  @open-kpi-source="handleOpenKpiSource"
/>
```

父容器必须有明确高度：

```css
.dashboard-gis {
  position: relative;
  width: 100%;
  height: 100%;
  min-height: 420px;
  overflow: hidden;
}
```

不要在地图组件内写死 `100vw` 或整个页面高度。

## 5. 正式 KML 加载逻辑

图层入口只有一个：

```text
public/gis/s1-6/layer-config.json
```

组件通过：

```ts
src/modules/traffic-gis-overview/config/design-map.config.ts
```

读取配置：

```ts
manifestUrl: "/gis/s1-6/layer-config.json"
```

### 道路生态基础图层

- ID：`road_ecology_base`
- 使用 `Cesium.KmlDataSource` 加载。
- 默认显示。
- 首次视角采用配置中的 `overviewRectangle`。
- KML 原始样式不统一改色。
- 堆渣线按 KML 原始对象稳定编号为“堆渣区1～8”。

### SPX 边坡图层

- ID：`slope_spx`
- 默认显示。
- 不使用原生 KML Entity 全量加载。
- `spx-kml.worker.ts` 在 Web Worker 中解析。
- `SpxPrimitiveLayer.ts` 按 KML 原始样式批量生成 Cesium Primitive。
- 第二次显示时复用缓存，避免重复解析。

不要把 SPX 改回 `KmlDataSource.load()` 全量实体方式，否则浏览器可能因大量元素崩溃。

## 6. 后台 ESG 异常点联动

地图设计数据和 ESG 业务数据是两条独立数据链：

```text
KML设计数据 → DesignKmlLayerManager → 道路、边坡、保护区、堆渣区
后台业务数据 → HttpTrafficAdapter → 超标、异常、风险、逾期点位
```

正式首页使用：

```vue
data-mode="api"
:design-only="false"
presentation-mode="dashboard"
```

接口根地址：

```text
/api/esg/gis
```

或设置：

```env
VITE_TRAFFIC_API_BASE=http://目标后台地址/api/esg/gis
```

接口包括：

```text
GET /layers
GET /features
GET /features/:featureId/relations
GET /features/:featureId/business-links
```

首页 `dashboard` 模式只接收后端返回的动态 API 图层：

```ts
layer.source.type === "api" && !layer.source.url
```

这样可防止目标项目中遗留的静态演示线、演示弃渣点等再次进入首页。

业务要素最小结构：

```json
{
  "id": "env-001",
  "layerId": "env-monitor-upload",
  "objectType": "environment-monitor",
  "name": "K12+300 水质监测点",
  "geometry": {
    "type": "Point",
    "coordinates": [108.75, 24.55, 0]
  },
  "properties": {
    "monitorFactor": "COD",
    "value": 123.85,
    "limit": 100,
    "unit": "mg/L"
  },
  "status": "超标",
  "updatedAt": "2026-08-04T10:00:00+08:00"
}
```

状态会被前端归一化：

| 后端状态 | 地图状态 |
| --- | --- |
| 正常、达标 | `normal` |
| 关注 | `attention` |
| 待复测、预警、异常 | `warning` |
| 超标、逾期 | `critical` |
| 离线 | `offline` |

## 8. 不应恢复或修改的内容

- 不要加入旧 `real-layers.json`。
- 不要恢复静态 `section-1`、`section-2`、`section-3` 演示路线。
- 不要恢复静态 `waste-1`、`waste-2` 演示弃渣点。
- 暂时不要显示 KML 中“取弃土场”“弃渣场”“0土场编号”和 `q数字` 要素。
- 不要修改两份 KML 的原始坐标和线型。
- 不要把 SPX 改成逐 Entity 全量加载。
- 不要在多个 Vue 组件中写死 KML 路径，统一维护 `layer-config.json`。
- 不要把 Cesium Viewer 放进 Pinia 等可序列化全局状态。

### 设计地图

- [ ] 页面首次进入能看到新的实际道路全线。
- [ ] 不出现旧彩色“1标段、2标段、3标段”演示路线。
- [ ] 基础 KML 和 SPX 均默认加载。
- [ ] 缩放和拖动无明显卡死。
- [ ] 基本农田和生态保护要素名称可见。
- [ ] 能看到“堆渣区1”至“堆渣区8”，近中距离显示、超远距离隐藏。
- [ ] 不出现密集的“取弃土场 323405”等错误标注。
- [ ] 点击 KML 对象可获得名称和所属设计图层。
- [ ] 复位视角回到新道路中心线范围。

### 业务联动

- [ ] 后台异常、超标、逾期点位能显示。
- [ ] 超标和逾期采用红色醒目标识。
- [ ] 点击点位能看到业务值、阈值、时间、坐标和状态。
- [ ] 接口失败只影响业务图层，不破坏底图和 KML。

## 10. 当前已知边界

- “取弃土场”源数据存在重复名称和错误文字，当前只隐藏，未删除源 KML。
- 堆渣区编号由 KML 中 8 个 `堆渣线_数字` 对象的数字后缀升序稳定生成；如果以后替换 KML，应重新核对编号与业务台账的对应关系。
- 历史影像的左右时间节点来自前端配置，接正式影像服务时需替换 URL。
- 在线底图和在线地形依赖网络；内网部署时必须替换为内网瓦片/地形服务。
- 后台业务点需要经纬度；没有坐标的数据不会自动出现在地图上。

## 11. 推荐迁移顺序

1. 先只启用 `design-only="true"`，确认两份 KML和视角。
2. 再启用底图切换、地形、历史对比和全屏。
3. 最后切换 `design-only="false"`、`data-mode="api"` 接业务异常点。
4. 完成后删除目标项目的旧地图组件引用和旧演示数据入口。
5. 按第 9 节逐项验收。
