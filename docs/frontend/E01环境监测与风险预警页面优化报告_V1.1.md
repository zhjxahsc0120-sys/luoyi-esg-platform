## 1. 数据链审计（先于改页）

### 1.1 API `GET /api/environment/e01/events`

| 项 | 实测（Demo `127.0.0.1:8765`） |
|---|---|
| `code` | `0` |
| `openPoints` 总数 | **3** |
| 按类型 | AIR=**1**，WATER=**1**，NOISE=**1**（1+1+1） |
| 样例点 | `11001` AIR / `RECTIFYING` / `exceedMultiple≈1.07`；`11002` WATER / `CLOSED`；`11003` NOISE / `CLOSED` |
| overview | `monitorPointCount=3`，`anomalyCount=2`，`openCount=1` |

结论：**Demo 数据已含空气/水质/噪声三类监测对象，无需补 Demo、未改 API 契约。**

### 1.2 前端映射与过滤

| 环节 | 结论 |
|---|---|
| `openPoints` | 直接使用接口 `payload.openPoints`，无二次裁剪 |
| `scopedPoints`（风险） | `isE01RiskPoint` → 仅超标/异常/未闭环等；实测约 **1** 点（AIR） |
| `scopedPoints`（全部） | 返回全部 `openPoints`，**未错误复用风险过滤** |
| `e01VisiblePoints`（Dashboard） | 先按 `pointScope`，再按 `categoryFilter`；逻辑与面板一致 |
| 分类过滤 | V1.0 默认 `categoryFilter='AIR'`，且「全部监测点」切换时**仍保留 AIR** |

### 1.3 根因（「全部监测点」只见 1 点）

- 接口与 all-mode 的 scope 过滤均正确，**不是**「全部模式误用风险数据」。
- 进入「全部监测点」后仍停留在默认业务分类 **空气监测**，列表/GIS 仅展示 AIR 子集 → 视觉上「只有 1 点」。
- WATER / NOISE 为 `CLOSED`（非风险），只在全部模式下应出现，却被 AIR 分类挡住。

**修复策略**：切换到 `pointScope='all'` 时将 `categoryFilter` 置为 `'ALL'`，一次列出空气+水质+噪声；分类卡片仍可再筛。切回风险模式时，若当前为 `ALL` 则回到 `'AIR'`。

## 2. 修改内容

### 2.1 Task 1 — 右侧字号层级（结构不变）

顺序保持：环境风险预警 → 统计 → 风险/全部 → 空气/水质/噪声 → 列表 → 分页。

| 元素 | 调整方向（约） |
|---|---|
| 标题 | 19px → 22px |
| 统计数字 / 文案单位标签 | 21/13 → 26/14；风险等级文案 16 → 18 |
| 范围切换 | 13px → 15px，高度 32 → 36 |
| 分类名 / 计数 / 选中态 | 12/16 → 14/20，选中加粗 |
| 列表名称 / 指标 / 检测值 / 状态标签 | 名称 15→17，检测值 15→17，状态标签 12→13 |
| 分页 | 摘要与按钮略放大 |

为容纳放大字号、避免内部滚动，`PAGE_SIZE`：4 → **3**（仍分页、无列表 `overflow: auto`）。

### 2.2 Task 2 — 全部监测点展示修复

- `DashboardPage.handleE01ChangeScope`：`all` → `categoryFilter='ALL'`；`risk` 且当前为 `ALL` → `'AIR'`。
- 空态文案：全部 + `ALL` 时为「暂无监测点」。
- **未改** Demo SQL / API 字段；GIS 点击/定位/弹窗逻辑不变。
