| 项 | 甲方 7.14 | 现网（2026-07-24 核查） | 差异 |

## 1. 目标与边界

### 1.1 目标

点击首页 S01 → 打开专属模态：展示连续天数、起算/当前日、计数状态、最近重置（若有）、工期阶段与简要结论；KPI 与详情同源。

### 1.2 本阶段不做

- 不做地图联动工作台；不做真实审批流 UI  
- 不把隐患/未遂/设备故障计入重置  
- 不与 S02 风险点混计  
- 不把「安全月报已上传」自动等同「建设单位已确认连续天数」  

### 1.3 成功标准

口径与甲方一致；起算日正确；重置门禁正确；正式/演示可隔离；页面信息克制（演示态对齐 E04 收敛原则：少角标、少证据说教）。

## 2. 口径与 KPI 主源

### 2.1 统计口径（冻结候选）

\[
\text{continuousDays} = (\text{currentDate} - \text{cycleStartDate}).\text{days}
\]

- `cycleStartDate` = 最近一次**已生效重置**的事故日；若无，则 = **开工令日 2026-05-08**  
- `currentDate` = 统计期末业务日（月度确认后的 `as_of`；演示默认与平台统计日对齐，建议 **2026-07-24**）  
- 按**自然日**；节假日、停工期不扣减  
- Python/`date` 差值为日期间隔天数（不含终点日当天若按「已满整天」理解）；**实施时须与验收样例勾稽表一致**（见 §6）  

**建议样例（无中断）：**  
`currentDate=2026-07-24`，`cycleStart=2026-05-08` → `77` 天（待审核确认是否采用「含首含尾」另一算法；V0.1 推荐保持现网 `(end-start).days` 并在勾稽表写死样例）。

### 2.2 重置条件（唯一）

仅当同时满足：

1. 安全生产责任事故；  
2. 存在**人员死亡**；  
3. 事故责任或等级**已认定**（未认定 → `countingStatus=pending`，**不改** `cycleStart`）；  
4. 业务标记 `interrupt_counting=1`（生效重置）。  

明确**不重置**：一般隐患、未遂、轻微伤害、普通设备故障。

### 2.3 KPI 唯一主源

| 模式 | 主源 | 说明 |
|------|------|------|
| 正式 | `safety_production_record`（`data_nature=formal`）+ 生效事故重置链 | 无正式确认批次时正式 KPI 可为空/0 策略待审 |
| 演示 | 同表 `data_nature=demo` / `is_demo=1` | 演示部署默认读演示行 |

首页 KPI 值 = `get_s01_detail().continuousDays`，禁止前端另用开工日重算覆盖（现前端有兜底重算，冻结后应**以后端为准**）。

### 2.4 首页展示（甲方要求）

- 主值：连续天数  
- 须可感知：**最近一次重置日期 / 原因**（无重置则展示「自开工令起未重置」或等价文案）  
- 统计起点固定文案：**2026-05-08**

## 4. 数据模型（增量，不推倒）

### 4.1 现表保留

- `safety_production_record`：周期主事实  
- `safety_incident_record`：事故与是否重置  
- `construction_stage_record`：工期阶段展示  

### 4.2 建议增量字段（P1）

**safety_production_record**

| 字段 | 用途 |
|------|------|
| `is_demo` / `data_nature` | 正式演示隔离 |
| `statistics_as_of` | 统计期末 |
| `confirmation_status` | `PENDING` / `CONFIRMED`（建设单位月度确认） |
| `confirmed_at` / `confirmed_by` | 确认审计（可空） |

**safety_incident_record**

| 字段 | 用途 |
|------|------|
| `has_fatality` | 是否人员死亡（重置硬条件） |
| `determination_status` | `PENDING` / `DETERMINED` / `NOT_APPLICABLE` |
| `is_demo` / `data_nature` | 隔离 |
| `effective_status` | `EFFECTIVE` / `INEFFECTIVE` |

### 4.3 测数重建原则

- `project_start_date` → **2026-05-08**  
- 无死亡责任事故 → 无重置；`continuousDays` 按 §2.1 重算  
- 工期阶段日期改到开工令之后（准备/主体等可压缩为演示阶段）  
- 验收基线测试中写死的 **368** 必须同步改掉（见任务单）
