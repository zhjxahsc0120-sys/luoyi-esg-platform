## 2. 产品定位

**一句话：** 助手面向「查清现状 + 向上级检查组说明合规与备齐材料」，不是「某部门自备迎检 checklist」。

| 维度 | 现行定位 | 已弃用 |
|------|----------|--------|
| 主语 | 如何向上级检查组说明合规与备齐材料 | 安环部/合约部自己要交什么 |
| 包名 | `上级检查_{环保\|安全\|综合}合规资料包_YYYYMM` | `安环部_迎检资料包_…` |
| 同答结构 | 库口径结论 + 进度表 + KPI + 下载资料包 | 仅清单或仅 KPI 计数 |
| 环保主口径 | **11 类**应备资料 + 文件归集进度；待补齐（≈4）是子集 | 「应备 4 项」作唯一标题 |

**红线：**

1. 禁止固定 FAQ 写死业务数字（数字必须走 API / 同源闸）。
2. 用户可见助手路径禁止 DEMO / 演示 / 功能验证。
3. 资料包 `nature: sample` 仅内部字段；UI 副标题用中性「合规资料包 · {账期}」。

## 3. 问答信息架构

```text
/#/assistant
  ├─ 欢迎区
  │    · 分类 chips：ESG指标｜环保/安全/治理｜碳｜月报｜资料档案｜应对上级检查
  │    · 推荐问（welcomeQuestions / 注册问题子集，含 C03/C04/C05）
  ├─ 用户提问
  │    → POST /api/assistant/ask  { question }   （主）
  │    → GET  /api/assistant/qa?question=…      （降级）
  ├─ 后端 assistant_qa.ask
  │    resolve_intent → INTENT_BUILDERS[intent] → message
  └─ 前端 AssistantMessage 渲染
       content → kpiCards? → tableData? → packageCard? → dataBasis? → followUps?
```

**API shape（摘要）：**

```text
POST /api/assistant/ask  { "question": "…" }
→ { code, data: {
     questionId, intentKey, matched,
     message: { content, kpiCards?, tableData?, packageCard?, dataBasis?, followUps? }
}}
```

**运维约束：** 改 `assistant_qa.py` 后须**重启后端**；否则前端易表现为「暂时无法连接问答服务」或旧逻辑。

## 4. 标准答法设计（核心）

### 4.1 通用 KPI / 清单类（如 Q01 未闭环环保问题）

**结构模板（固定顺序）：**

1. **结论句** — 截至时点 + 总数 + 关键分项（如整改中/待复查/待销项）
2. **kpiCards** — 3～5 枚，与结论一致
3. **tableData** — 前 N 条清单（通常 5）；可有「查看全部」文案（引导工作台，非助手内分页）
4. **dataBasis** — 口径说明 + 同源表/KPI
5. **followUps** — 同域追问（逾期 / 按部门 / 标段 / 导出提示）

**空态：** 明确「暂无…」+ 仍给 `dataBasis`（口径不变），不造假数。

**错误态（builder 抛错）：** 「查询「{intent}」时数据暂不可用…」+ 少量 followUps；**不要**冒充空业务。

---

### 4.2 上级环保检查（C03 · `pack.superior_env`）— 目标答法

**结构（必须齐全）：**

1. **证据链叙述** — 「审批要求→现场实施→监测检查→问题整改→复查销项」+ **11 类**备齐说明  
2. **编目进度** — 应备具体文件 N / 已归集 / 待补齐（现演示编目 46 / 42 / 4，**待批复重算**）  
3. **运行态** — 当前未闭环（E02 同源）+ 历史闭环率 `a/b`  
4. **待补齐提示** — 点名 pending 文件（或对照 G04）  
5. **同答资料包** — 「已附…可直接下载」  
6. **kpiCards（6 枚优先）：** 应备资料类别 11｜应备具体文件 N｜已归集｜待补齐｜当前未闭环｜历史问题闭环率  
7. **tableData：** 「上级环保检查 · 11类应备资料进度」（01–11）  
8. **packageCard：** 标题「上级环保检查 · 合规资料包」+ stats chips +「下载资料包」  
9. **dataBasis：** 写明「不以应备仅 4 项为主口径」

**禁止：**

- 仅甩「未闭环 N、待补齐 M」两行无表  
- PackageCard / 标题以「应备 4 项」作主叙事（4 只是 pending 子集）  
- 用户可见 DEMO/演示字样  

**静态 vs 实算：**

| 指标 | 性质 |
|------|------|
| 11 类 / N / 已归集 / 待补齐 | 资料包 manifest **编目静态**（手维） |
| 未闭环 / 闭环率 | **运行时实算**（与首页 E02 同闸） |

---

### 4.3 上级安全 / 综合 — 现状答法 vs 目标答法

| | **现状（已实现）** | **目标答法（待补齐）** |
|--|-------------------|------------------------|
| **安全 C04** | 短叙述 + S02 在管数 + 稀疏「应备资料」表 + 3～4 文件包 | 类别化证据链（风险辨识→管控→隐患整改→应急演练→费用台账→上级核查）+ stats chips（类别/文件/已归集/待补齐 + S02 运行态）+ PackageCard；**不必照搬环保 11 类名** |
| **综合 C05** | 环保/安全/G01/G04 摘要拼装 + 稀疏综合包 | 「环保摘要 + 安全摘要 + G01/G04」索引式综合包 + 清晰跳转 followUps（勿冒充环保 11 类副本） |

---

### 4.4 未命中 / 空 / 错 / 服务不可达

| 场景 | 行为 | 用户感知 |
|------|------|----------|
| **未命中意图** | `matched: false` + `build_fallback` 列出可问清单（含应对上级检查） | 「暂未识别…您可以尝试」——**不是**服务挂了 |
| **业务空** | `_empty_message` 明确「暂无」+ dataBasis | 真零态 |
| **builder 异常** | 数据暂不可用 + 追问 | 库/API 故障 |
| **HTTP 失败** | 前端 `fallbackAnswer`：「暂时无法连接问答服务」 | **运维问题**；勿与未命中混淆 |
| **短问「本月月报」** | 现路由偏严（需「待处理/准备」等）→ 易未命中 | **待修**（见 §7） |

## 9. 验收要点（助手问答）

1. 打开 `/#/assistant`：欢迎区有「应对上级检查」；推荐问含 C03/C04/C05。  
2. 问 C03 → 见证据链叙述、11 类表、6 类 stats chips、PackageCard、「下载资料包」；解压见 `00`–`11`。  
3. 问 Q01 → 未闭环总数与首页 E02 **一致**（同环境闸）。  
4. 问 Q04 → 无整表「—」空壳；无数据则空态文案而非假行。  
5. 全文目视：回答区无「DEMO / 演示 / 功能验证」。  
6. 故意短问「本月月报」：记录现状（未命中或命中）；修路由后应进 `monthly.pending`。  
7. 停后端再问 → 「暂时无法连接问答服务」（运维对照）。  
8. 改 `assistant_qa.py` 后**重启**再 curl：

```bash
curl -s -X POST http://127.0.0.1:8787/api/assistant/ask ^
  -H "Content-Type: application/json" ^
  -d "{\"question\":\"应对上级环保检查应准备哪些合规资料？\"}"
```
