## 3. KPI 唯一主源与防重复（可实施级）

### 3.1 唯一累计事实

> **E04 唯一累计事实**来自「**当前生效核算批次**（`accounting_batch_id`）中的**活动排放结果**」。

```text
E04(scope) = SUM( activity_emission_result.emission_amount )
  WHERE accounting_batch_id = 该 scope 下 current / EFFECTIVE 批次
    AND 批次.boundary_version = 该 scope 采用的边界版本
    AND 结果行 is_current = 1（或等价「未被替代/作废」）
    AND 满足 §2.7 的 data_nature / effective / verification 谓词
```

物理表可仍落在 `carbon_emission_activity`（或明确的结果表）；关键是：

1. **有核算批次**；  
2. **有当前有效标志**；  
3. **按边界配置过滤来源**（见 §5），而不是改历史活动上的 boundary 权威字段。

### 3.2 粒度与唯一键

活动排放结果的业务唯一键（同一当前有效集内）：

```text
project_id
+ accounting_period   -- 建议月：YYYY-MM
+ source_code
+ activity_key        -- 稳定业务键，禁止空撞车
+ data_nature
+ accounting_batch_id -- 或「批次内唯一」+ 全局 current 指针
```

同一 `project + accounting_period + source_code + activity_key + data_nature` **只能有一条当前有效核算结果**。  
被替代、作废、重算前版本：`is_current=0` / `superseded_by`，**不进入当前累计**。

### 3.3 材料明细主从关系（冻结）

- `carbon_material_usage`（或等价）＝材料来源的**下钻明细**。  
- 材料排放已汇总进活动/结果表中 `source_code=material` 的那一行（或等价汇总行）。  
- **禁止** `SUM(activity) + SUM(material_usage)` 双重相加。  
- 勾稽：材料分项合计 ＝ 主要材料来源值（见 §6）。

### 3.4 标段

- 标段明细表＝分析拆分，**不是**第二套可与全线活动再求和的事实。  
- 全线累计 **不得** 再对标段表 SUM 后与活动表相加。

### 3.5 禁止计入 E04 主值的量

减排量、措施预计减排、成本、强度、边界对照试算值（11,970.96）、运输在**候选正式边界**下的对照——均**不进入** E04 主值。  
（演示边界下运输仍按已冻结包计入 12,856。）

## 5. 数据库重设计（增量）

### 5.1 沿用表族

不推倒 `carbon_emission_activity`、`carbon_emission_factor`、`carbon_material_usage`、segment/baseline/reduction/measure/evidence_link 等；**独立迁移**，不改历史建库脚本，不进 E 组闭环迁移域。

### 5.2 边界与活动事实分离（冻结）

| 对象 | 职责 |
|------|------|
| 活动/结果记录 | 保存活动事实、`source_code`、量、**结果行 `factor_snapshot_id`** 等；**不把 boundary_version 当作可批量改写的权威计入开关** |
| `carbon_accounting_boundary` | `boundary_version` + **`boundary_status`** + `source_code` + `in_boundary` + 生效说明 |
| 核算批次 / 结果快照 | `accounting_batch_id`、采用的 **`boundary_version`（须 ACTIVE）**、`statistics_as_of`、期间、性质、核验态、`is_current` |
| 切换边界 | **新批次 + 新快照**；禁止批量 UPDATE 历史活动以「切换版本」 |

允许活动行上冗余缓存「写入时边界」仅作审计，**权威过滤以批次所选边界配置为准**。

#### 5.2.1 边界生命周期（V0.3 冻结）

| `boundary_status` | 含义 |
|-------------------|------|
| `DRAFT` | 草稿，不可被正式 current 批次引用 |
| `CANDIDATE` | 候选边界，**仅只读对照试算**；**不得** 正式 current / 正式 KPI |
| `ACTIVE` | 当前可被选为正式核算的生效边界 |
| `RETIRED` | 已退役，仅供历史批次只读追溯 |

**规则：**

- 正式 **current** 批次**仅**引用 `boundary_status = ACTIVE` 的边界版本。  
- **`CANDIDATE` 仅对照**，不得作为正式 current、不得进入正式 KPI（含首页 E04 主值）。  
- 同一 **project + data_nature + 统计口径** 下，**至多一个 ACTIVE**。  
- **确认生效**＝新建 ACTIVE 版本，或将候选**审批为 ACTIVE** 并配合**新正式批次**；**禁止**原地改写已被历史批次引用的边界内容。  
- 演示通道：`DEMO-BOUND-E04-20260718` 在演示通道上视为 **ACTIVE**（与正式通道隔离）。  
- **`platform_calc` → 正式**：仅通过**新正式批次**纳入；**禁止**原地变更 `data_nature` 或把测算结果悄悄并入正式 current。

### 5.4 结果行不可变因子快照（冻结要求）

**硬约束：** 每条 `activity_emission_result` **必须**绑定不可变 **`factor_snapshot_id`**；快照实体承载下列因子字段（一旦被历史批次引用则**不可变**）：

1. 因子名称及版本  
2. 因子来源文件/机构  
3. 分子、分母单位  
4. 活动单位  
5. 单位换算系数与换算路径  
6. 生效时间及适用范围  
7. GWP 或折算依据版本  
8. 计算精度与最终舍入规则引用  
9. **核算时因子快照内容**（行级），保证旧累计可原样复算  

**批次与快照关系：**

- 批次层仅保存：本批采用的**快照 ID 集合** + **规则/舍入版本**；**不得**通过批次级操作替换或改写结果行与快照的关联。  
- 任一纳入正式汇总的结果行若 **缺少 `factor_snapshot_id` 或快照缺失** → 该批/该行 **不得标记为 VERIFIED**。  

（原「批次级单一快照包」表述废止；以**行级不可变快照**为准。）

### 5.5 正式 KPI 谓词（草案，取代 IFNULL 默认）

```sql
-- 正式 E04：必须显式 EFFECTIVE + 已核验 + formal + 当前批次
-- （表名以实施时批次/结果模型为准）
WHERE data_nature = 'formal'
  AND is_demo = 0
  AND effective_status = 'EFFECTIVE'   -- 禁止 IFNULL(...,'EFFECTIVE')
  AND verification_status = 'VERIFIED'
  AND is_current = 1
  AND accounting_batch_id = :current_formal_batch
-- 来源是否计入由该 batch.boundary_version 关联 carbon_accounting_boundary.in_boundary=1
```

空 `effective_status` → 待核实清单，不计入。

### 6.3 精度规则（冻结）

| 层 | 规则 |
|----|------|
| 活动量 | **原始精度**入库/入算，**禁止**为页面展示先截断再参与汇总 |
| 排放因子 | `DECIMAL(20,8)`（或现有字段精度 **≥ 此**） |
| 行级中间量 | `DECIMAL(24,8)` |
| 批次聚合 | 对**未舍入**的行级中间量 **SUM**，再 **`ROUND(..., 2)`** |
| 舍入模式 | **`ROUND_HALF_UP`** |
| 页面展示 | **仅**展示两位小数；展示值**不得**回灌聚合或 KPI 计算 |
| **禁止** | 分量先 `ROUND` 再相加；前端重算累计或补尾差 |
