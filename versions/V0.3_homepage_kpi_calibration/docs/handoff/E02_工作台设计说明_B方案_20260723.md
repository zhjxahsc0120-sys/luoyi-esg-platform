## 2. 口径与 KPI 主源

### 2.1 统计口径

当前未闭环环保问题事项数；一事项只计 1；撤销/合并/已闭环不计。  
正式过滤：`is_demo=0`、`data_nature=formal`（及有效状态）；甲方无真实未闭环 → **正式 KPI = 0**。

### 2.2 闭环条件（唯一）

> 整改完成 + 复查通过 + 可追溯销项确认 → 已闭环。  
> 仅复查通过不得减 KPI。

### 2.3 KPI 唯一计数主源（冻结）

| 阶段 | 正式 KPI 唯一主源 | 案卷表角色 |
|------|-------------------|------------|
| **切换前（当前→P3 前）** | **`env_issue_record` 仅此一张** | `e_closure_case` 只补充闭环展示（进度/轨迹/材料/责任），**不参与 KPI 相加** |
| **切换后** | **`e_closure_case`（`E02_ENV`）仅此一张** | 台账表可继续作事实源，但 KPI 只读案卷 |

硬规则：

- **任何阶段不得将两表结果相加**  
- 关联与去重：`e_closure_case.source_table='env_issue_record'` + `source_record_id` **一对一**；同一 `source_record_id` 不得挂多条有效 E02 案卷计入存量  
- 切换时机：工作台 API 与双轨对账稳定后，在实施单中明示「切主源」；切换前后各验一次正式计数  

### 2.3.1 P1 演示数据写入与切换前计数（冻结）

P1 每条演示事项**必须同时写入**：

1. `env_issue_record`（`is_demo=1`、`data_nature='demo'`；若表缺字段须先迁移补齐）  
2. 对应 `e_closure_case`（`case_domain='E02_ENV'`、`data_nature='demo'`、`is_demo=1`）  
3. 通过 `source_table='env_issue_record'` + `source_record_id` **一对一**关联  

切换前计数规则：

| 模式 | 唯一计数表 | 过滤 |
|------|------------|------|
| 正式 | `env_issue_record` | `is_demo=0` AND `data_nature='formal'` 且未闭环等 |
| 演示 | `env_issue_record` | `is_demo=1` AND `data_nature='demo'` 且未闭环等 |

- `e_closure_case` **只提供闭环详情**（进度/轨迹/材料/责任），**不参与**切换前 KPI 数字  
- 演示与正式**不得合并**为一张卡片数字  
- 若仅写入案卷、不写台账 → **禁止**（会导致演示卡片与主源规则不一致）  

切换前正式计数示例：

```
env_issue_record
  WHERE issue_status NOT IN ('已闭环','已撤销','已合并')
    AND is_demo=0 AND data_nature='formal'
```

切换前演示计数示例：

```
env_issue_record
  WHERE issue_status NOT IN ('已闭环','已撤销','已合并')
    AND is_demo=1 AND data_nature='demo'
```

切换后（正式）：

```
e_closure_case
  WHERE case_domain='E02_ENV'
    AND is_demo=0 AND data_nature='formal'
    AND effective_status='EFFECTIVE'
    AND current_status NOT IN ('CLOSED','CANCELLED','MERGED')
```

### 2.4 责任与材料类型 / E01·E03 边界

同 V0.2：发现=宜罗/上级+正式通知；整改=问题单位；复查销项=宜罗。E01/E03 KPI 互斥。

## 5. 一级总览面板

### 5.1 尺寸

- 宽度：**复用 E01 实际容器**（`.dashboard-right` / 既有工作台槽），不另写死 66/34；冻结实现时回填 CSS 变量、min/max 宽  
- 高度：占满右侧工作区，不挤施工时间轴  
- 笔记本：统计可换行；分页栏始终可见  

### 5.2 统计条（状态映射冻结）

| 一级统计项 | 包含 `current_status` |
|------------|----------------------|
| **整改中** | `DISCOVERED`、`PENDING_RECTIFICATION`、`RECTIFYING` |
| **待复查** | `PENDING_REVIEW` |
| **待销项** | `PENDING_CLOSURE` |
| **暂缓** | `SUSPENDED`（仅真实业务启用后展示；有数据则单独成格） |

等式：

```
全部 = 整改中 + 待复查 + 待销项 [+ 暂缓（若启用）]
```

- **逾期**：叠加属性 / 「其中逾期 m」或可勾选标签；已计入上式，不可与状态格相加  
- `CANCELLED` / `MERGED` / `CLOSED`：不进「全部」  

台账中文映射：已发现/待整改、整改中 → 统计「整改中」；待复查；待销项；已闭环等。

### 5.3 列表与分页

行：类型·位置｜状态｜名称｜整改单位｜期限（逾期标红）｜无 GIS「无法定位」。  

分页：**默认每页 3 条**（单项信息量大于 E01 时可维持 3）；可按工作区高度在实现时定为常量，**同一分辨率下不得动态跳变**；分页栏始终可见。

### 5.4 一级交互 / 空态

点统计→筛状态+重置页；点逾期→叠加；点行→选中+高亮几何+开二级；点地图要素→见 §10.3 多事项规则。  
空态：正式 0 / 筛选无结果 / 加载中 / 接口失败+重试。  
关工作台：退出模式、清选中与高亮、回首页默认态。

## 6. 二级闭环分析弹窗

### 6.1 定位与避让（冻结）

- 锚点：关联对象可视中心（线中点 / 面质心或包围盒中心）；**仅 UI，不反写正式坐标**  
- 地图 `flyTo` / 适配：**按扣除一级面板后的有效可视区**计算；计入左边距、顶栏工具条、底栏时间轴安全边距  
- 弹窗随地图平移/缩放**持续重算**屏幕坐标  
- 优先锚点右上；越界翻转；**右侧空间不足优先翻到对象左侧**；再与顶/底冲突则下翻或上翻  
- 点/线/面若超出有效可视区 → **重算视野**后再定位弹窗  
- 建议宽 360～400px；高不超过有效可视区约 70%，内部滚动  

### 6.2 内容骨架

进度条（发现→整改→复查→销项→闭环）｜当前进展一句｜责任主体｜页签（进展轨迹 / 证据）｜期限与逾期。  
复查退回须展示原因。不重复「仅名称+状态+责任+期限」四件套当唯一内容。

### 6.3 关闭行为（唯一，冻结）

关闭二级（`×` / Esc）或**点击地图空白**时，**一律**：

1. 保留一级筛选条件与页码  
2. 保留当前地图视角（不飞回全范围）  
3. 取消当前事项选中与单对象强高亮  
4. 恢复为**当前筛选结果**的普通高亮集合  

不保留「可选清除/保留选中」二选一。

### 6.4 二级状态（须实现）

| 状态 | 行为 |
|------|------|
| 加载中 | 骨架/文案「正在加载…」 |
| 详情失败 | 错误文案 + **重试** |
| 无轨迹 | 「暂无状态轨迹」 |
| 无证据 | 「暂无证据材料」（按门禁仍可标缺失角色） |
| GIS 已删除/无法加载 | 「空间对象不可用」；弹窗落在有效区安全默认位，不造假点 |

### 6.5 材料入口（禁止伪按钮）

| 条件 | 展示 |
|------|------|
| 有附件且已实现预览 | **预览** |
| 仅支持下载 | **下载** |
| 无附件 | **暂无材料**（不可点） |
| 尚未实现预览 | **不得**放点击无反应的按钮 |

**不提供「发起督办」入口。**

## 7. 状态机

主路径：整改中 → 待复查 → 待销项 → 已闭环；逾期为属性；复查不通过 → 回整改中（轨迹保留）。  
英文：`DISCOVERED`→`PENDING_RECTIFICATION`→`RECTIFYING`→`PENDING_REVIEW`→`PENDING_CLOSURE`→`CLOSED`；分支 `CANCELLED`/`MERGED`/`SUSPENDED`。

进入条件同 V0.2（通知→整改→复查通过进待销项→销项确认进闭环）。

## 8. 材料完整度（退回轮次，冻结）

### 8.1 概念

| 指标 | 含义 |
|------|------|
| 闭环进度 | 当前流程阶段（进度条） |
| 材料完整度 | **必需证据角色是否覆盖**（按角色，不是附件文件个数） |

门禁依据：

> **当前整改轮次 + 历史上已到达的最高流程阶段 + 状态轨迹**，而非「只看 current_status」。

### 8.2 基线：未发生退回时，按已达最高阶段

| 已达最高阶段 | 必需角色 |
|--------------|----------|
| ≤ 整改中 | `FORMAL_NOTICE`（或 `INITIAL_REPORT`） |
| 曾到 / 正在 待复查 | + `RECTIFICATION_MATERIAL`（当前轮次） |
| 曾到 / 正在 待销项 | + `REVIEW_OPINION`（有复测再 + `RETEST_REPORT`） |
| 已闭环 | + `CLOSURE_DOCUMENT`（或 §8.4 等价销项确认记录） |

### 8.3 复查退回（至少保留）

退回至「整改中」后，完整度**不得**塌缩成「仅通知单 = 1/1」：

- 正式通知单（仍必需）  
- **上一轮**整改材料（已发生，保留覆盖）  
- 复查意见或**退回记录**（`REVIEW_OPINION` / 轨迹等价证据）  
- **本轮**整改材料：状态为待补（完整度分母含本轮 `RECTIFICATION_MATERIAL`，分子仅本轮已交才计入）  

计算：`completeness = |已覆盖必需角色| / |必需角色|`；区分「历史已齐 / 本轮待补 / 后续未到期（灰显）」。

### 8.4 等价销项确认记录（冻结）

无独立销项文件时，**仅当**同时满足以下条件，方可等价覆盖 `CLOSURE_DOCUMENT` 角色：

| 条件 | 要求 |
|------|------|
| 存储 | 写入 `e_case_evidence`（`evidence_role='CLOSURE_DOCUMENT'`），可关联正式操作记录 / 结构化确认载荷；或证据元数据中明确 `evidence_kind=CLOSURE_CONFIRMATION` |
| 字段 | 必须含：**确认人**、**确认时间**、**确认意见**、**依据**（文书号/检查记录引用等） |
| 权限 | 写入时通过权限校验（宜罗侧销项权限）；演示数据可模拟权限通过但须 `is_demo=1` |
| 排除 | **普通** `e_case_status_history` 状态变更行（如仅 to_status=CLOSED 无确认载荷）**不得**视为销项证据 |

有独立销项附件时：仍以附件型 `CLOSURE_DOCUMENT` 为准；确认记录可作为补充，不重复计角色。

## 10. GIS

- 高亮真实点/线/面；禁止统一虚拟问题点；无关联标「未关联」  
- API 用 `spatialLinks`（`featureId`,`geometryType`,`role`），避免暗示全是点的 `mapPoints`  
- **一 GIS 对象关联多个 E02 事项**：不得随机打开一项；先弹出**关联事项选择列表**，用户选定后再开二级  
- **演示 GIS（冻结）：** 演示事项可**关联系统已有真实 GIS 要素**以验证联动；**不得修改正式要素几何/属性**；**不得**使用户误认为该真实位置确实发生过该环保问题；卡片/工作台/二级弹窗须**持续显示「演示数据」**
